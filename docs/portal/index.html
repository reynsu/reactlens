01 — Origin · Thesis · Principles

Why this project exists

Every existing E2E tool — Playwright, Cypress, QA Wolf, Octomind, Mabl — treats the application as a black box. They see HTML, accessibility trees, and pixels. They never see what your tool sees: a tree of <Component>s with props, state, hooks, and a known relationship to your source files. That is reactlens's entire moat. Everything flows from it.

A failing E2E test asks two expensive questions

Today, developers answer both manually. A stack trace and a screenshot don't help much.

  1. Is this a test bug or a real bug? (takes 90% of triage time)
  2. If it's a real bug, where exactly in my code? (the other 10%)

Tools that only see the DOM can't answer either question — they guess. Tools that also see the component tree, the props, the hooks, and the git history of both spec and component can.

The five principles that guide every decision

Captured in CLAUDE.md §10. Each one has shown up as a concrete tradeoff at least once during development.

PRINCIPLE 01

Capture is sacred, processing is replaceable

The component:snapshot data captured during a run is the foundation. If capture is incomplete or wrong, no amount of clever AI prompting saves us. If capture is rich and accurate, even mediocre prompts produce useful results.

PRINCIPLE 02

Confidence must be calibrated, not asserted

A diagnosis that says “high confidence” must actually be right at high frequency. We maintain an eval set of hand-labelled failures and measure accuracy per confidence level. If calibration regresses, we don't ship.

PRINCIPLE 03

Local-first, always

Everything runs on the developer's machine. The Anthropic API is the only network call, and only when the developer explicitly invokes generation or diagnosis. No telemetry. No cloud sync.

PRINCIPLE 04

One framework, deeply

Every time we're tempted to make it work for Vue too, we lose part of the moat. The component bridge depends on React-specific internals via bippy and that is the entire point.

PRINCIPLE 05

The diagnosis is always actionable

A diagnosis without a concrete suggested fix is a bug in our system. If we can't produce a patch, we say so explicitly and explain what additional information would let us — never a vague “try adding waits.”

Goals

  • React-only, deeply. The component-tree integration is the moat.
  • Local-first. Everything runs on your machine. No telemetry.
  • Two questions answered for every failure: test bug or real bug? Where exactly?
  • Page Object Model is the only test pattern we generate.
  • Zero-config for common React stacks.

Non-goals

  • We do NOT support Vue, Svelte, or Angular.
  • We do NOT support Cypress, WebdriverIO, or Selenium. Playwright only.
  • We do NOT host anything in the cloud.
  • We do NOT auto-apply fixes without explicit user confirmation.
  • We do NOT replace developer judgement — generated artifacts are starting points.
02 — Technical map & current state

How it's built, where each piece is

Three layers of moving parts: the component bridge (in your app), the Playwright runner (your tests + our reporter), and the dashboard / analyzer (where signals converge and diagnosis happens). Below: the architecture, the event protocol, and a map of where every phase stands today.

System architecture

reactlens run is the orchestrator. It spawns Playwright with a streaming reporter, starts the dashboard server on port 7777, and injects a probe into every page via page.addInitScript. The probe subscribes to React fiber commits using bippy, walks the tree, sanitises props/hooks, and ships component:snapshot events over WebSocket. On failure, the diagnosis agent reads the latest snapshot, the component source, the spec, and recent git history — then emits a classified Diagnosis.

03 — Usage · Examples · Docs

Try it on your own React app

reactlens is a single npm package with five subcommands. The init command copies templates into your project; everything else runs against your existing source. Below: quickstart, command reference, common scenarios, and links to the long-form docs.

Quickstart — zero to first diagnosis in < 5 min

For a Vite + React Router project. Other stacks (Next.js App Router, TanStack Router) are detected; templates are still landing for those.

# 1 — install reactlens as a dev dependency
pnpm add -D reactlens

# 2 — one-time setup: copies templates, installs @playwright/test + msw
npx reactlens init

# 3 — AI writes tests by reading your component tree + source
ANTHROPIC_API_KEY=sk-... npx reactlens generate

# 4 — open the dashboard, run tests, diagnose failures
npx reactlens run

Don't want to use the API? Add --use-claude-code to any AI-consuming command (generate, run, regen, analyze) and it routes through your local claude CLI binary — bills against your Claude.ai/Max subscription. Local development only.

Commands

CommandWhat it does
reactlens initDetect your stack, copy playwright.config.ts, reactlens/*.ts, reactlens.config.ts into your project. Install @playwright/test + msw. Idempotent (--force to skip prompts).
reactlens generateFor each component matching componentGlobs, AST-analyse its visual states, then ask Claude to write a Page Object + spec covering all of them. Runs tsc --noEmit on output. Requires ANTHROPIC_API_KEY or --use-claude-code.
reactlens runStart dashboard at localhost:7777, run Playwright with the streaming reporter, capture component snapshots + CDP screencast, and (when AI is available) diagnose each failure with classification + confidence + suggested patch.
reactlens regenHash each component source; regenerate only those whose hash changed. Cache at .reactlens/cache.json.
reactlens analyze <report>Read a Playwright JSON report and write a Markdown diagnostic summary for failed tests. Designed for CI artifacts.

Common scenarios

scenarioI want to generate tests for a fresh Vite app

generate reads each file matching componentGlobs in your reactlens.config.ts (default src/pages/**/*.tsx). For each one it enumerates the visual states via AST (conditional renders, query states, useState branches, error boundaries), passes that list to Claude as part of the prompt, and asks for a Page Object + spec that exercises every state. MSW handlers are referenced from src/mocks/handlers.ts. 

# All components in scope
ANTHROPIC_API_KEY=sk-... npx reactlens generate

# Just one
ANTHROPIC_API_KEY=sk-... npx reactlens generate --pages 'src/pages/Login.tsx'

Generated files land in e2e/pages/ and e2e/specs/. Run them with npx reactlens run or directly with npx playwright test.

scenarioI want to diagnose a failing CI test

Two paths. Inside an interactive run, the dashboard streams the diagnosis as the agent writes it; the DiagnosticsPanel renders classification, confidence, evidence, suggested fix, and (when applicable) a patch with rationale.

From a Playwright JSON report on disk (e.g. a CI artifact):

ANTHROPIC_API_KEY=sk-... \
  npx reactlens analyze playwright-report/results.json > diagnoses.md

Each failed test yields a Markdown block with classification ∈ {real-bug, test-bug, flaky, env-issue}, confidence ∈ {high, medium, low}, root-cause line, evidence bullets, suggested fix, and the most recent git commits touching both spec and component.

scenarioI want to run in CI without a dashboard

--ci disables the dashboard and the auto-open, runs Playwright with the streaming reporter so stdout is JSONL, and writes diagnoses (when API/claude-code is available) to reactlens-diagnoses.json at the project root. 

# GitHub Actions excerpt
- name: Run E2E with diagnoses
  env:
    ANTHROPIC_API_KEY: ${{ secrets.ANTHROPIC_API_KEY }}
  run: npx reactlens run --ci

- name: Upload diagnoses
  if: always()
  uses: actions/upload-artifact@v4
  with:
    name: diagnoses
    path: reactlens-diagnoses.json

Exit codes: 0 all pass · 1 any failed · 2 infra error.

scenarioI want to use my Claude.ai/Max subscription instead of API tokens

Install the claude CLI, log in with claude login (or use the Claude desktop app), then add --use-claude-code to any AI-consuming command, or set REACTLENS_USE_CLAUDE_CODE=1 in the env: 

# Per-command
npx reactlens generate --use-claude-code --pages 'src/pages/Login.tsx'
npx reactlens run --use-claude-code

# Or for the shell session
export REACTLENS_USE_CLAUDE_CODE=1
npx reactlens run

Local development only. Anthropic's TOS prohibits third-party distributed tools from leveraging Claude.ai login. Don't ship a product that depends on this flag.

Configuration cheat-sheet

// reactlens.config.ts — auto-generated by `init`
import { defineConfig } from 'reactlens/config';

export default defineConfig({
  componentGlobs: ['src/pages/**/*.tsx', 'src/components/**/*.tsx'],
  output: {
    pages: 'e2e/pages',
    specs: 'e2e/specs',
  },
  msw: { handlers: 'src/mocks/handlers.ts' },
  dashboard: { port: 7777, open: true },
});

All fields have sensible defaults; you can omit any of them. Validated by zod at load time — invalid configs throw a ConfigError pointing at the offending key.
