# Corpus harvest hosts live as forked OSS repos, not as localFixturePath fixtures

`harvest-corpus.json` supports two source modes: `localFixturePath` (the host app lives inside reactlens at `tests/fixtures/`) and `repoUrl + commitSha` (cloned on-demand from a remote git repo). Only one entry — `counter-fixture` — currently exercises the local mode, and it is intentionally trivial: a single `<Counter>` with a one-line planted regression. When ADR-0004's (δ) channel needs to grow beyond counter-like cases — host apps with custom hooks, context providers, reducers, and multi-level prop drilling so that planted failures can be **component-tree-distinguishable** instead of counter-like — the host app stops being a 1-file fixture and becomes a 30–50 component application with its own `package.json`, lockfile, build config, and dev server. Copying that into `tests/fixtures/` would inflate the reactlens repo, fight reactlens' own toolchain, and — worse — blur the (δ) vs (α) boundary by making the host app feel like maintainer-authored code that just happens to live in a `fixtures/` directory.

**Decision:** any corpus harvest host more substantial than a counter-fixture-class smoke target lives as a **fork of an upstream OSS repo under `github.com/reynsu/`**, pinned by `commitSha` in `harvest-corpus.json`. `counter-fixture` stays as `localFixturePath` because its role is to smoke-test the harness offline, not to represent real (δ) work. The fork preserves upstream git history (authorship, blame, original commits) — which is what makes (δ) honest: the diagnosis agent is reasoning about code the maintainer did not write. Adding Playwright suites or MSW handlers on top of the fork is acceptable scaffolding; the planted failures themselves must land in upstream-authored files.

**Consequences:**

- `counter-fixture` remains the sole `localFixturePath` entry and is documented as the harness smoke test, not a representative case.
- New hosts follow the pattern: fork upstream → push to `github.com/reynsu/<host-name>` → add Playwright suite + commit → pin that commit's sha → entry in `harvest-corpus.json` uses `repoUrl + commitSha`.
- ADR-0003 sovereignty-first is preserved: the harvest script still runs locally, network access happens only when an operator invokes `pnpm tsx scripts/harvest-eval.ts`, and no telemetry leaves the machine.
- Reproducibility comes from the pinned sha, not from co-location — anyone with network access can reproduce the exact case set, and the fork's history protects against upstream force-pushes or deletions.
- The reactlens repo does not grow proportionally to the number of hosts. Cost of adding a new host is one `harvest-corpus.json` entry + one fork, not a directory tree under `tests/fixtures/`.
- Trade-off acknowledged: CI cannot exercise the remote-clone path without network. This is acceptable because the smoke test in `tests/integration/harvest-eval.test.ts` uses `localFixturePath` (counter-fixture), and remote-mode runs are operator-invoked, not part of the default test suite.
- If a future host needs to be deleted from `github.com/reynsu/` (org cleanup, license issue), the corresponding emitted cases under `tests/diagnostic-eval/cases/synthetic-from-corpus/<host>/` remain valid — they are checked-in artifacts; only future re-harvesting would break.
